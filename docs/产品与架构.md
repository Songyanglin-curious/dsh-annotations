# 产品与架构

## 定位

Annotations 是 DSH 的通用批注能力，不依赖 Sift。它负责把用户意见准确锚定到原内容，并作为结构化上下文加入当前会话；文件修改、Diff 和工作区管理继续由 DSH 或其他插件负责。

## 组件

```text
SelectionCapture → SurfaceRegistry → TextAnchor
        ↓
AnnotationPopover → TurnStore → DSH Input Reference
                              ↓
                         AnnotationDock
```

- `SelectionCapture`：监听受支持 Surface 内的选区。
- `SurfaceRegistry`：将 DOM 选区解释为对话消息、文件或第三方内容来源。
- `TextAnchor`：保存字符范围、原文、前后文和内容指纹。
- `TurnStore`：按会话隔离本轮批注。
- `Input Reference`：复用 DSH 原生引用 chip 和序列化通道。

## 依赖方向

```text
DSH 原生对话 ───────┐
Markdown / 其他插件 ─┼─ Surface Adapter → Annotations → DSH 本轮输入
Sift Reference ─────┘
```

Annotations 不导入 Sift。Sift 只实现很薄的 Surface Adapter，并在检测到 Annotations 后注册自己的 Reference、Conversation Group 等可批注区域。发现协议同时支持就绪事件和主动请求，因此不依赖插件加载先后顺序；未安装 Annotations 时，Sift 的其余功能保持可用。

## 给 AI 的上下文

每条批注发送时包含：稳定来源 URI、来源类型、字符起止位置、内容指纹、被选原文、前后文和用户意见。字符位置便于直接定位；原文和前后文用于内容变化后的再次确认。插件本身不直接修改文件，最终修改仍由当前会话中的 AI 和宿主工具完成。

## 扩展方向

插件公开 `registerSurface()`。Sift 只需注册 Reference 卡片和 Conversation Group 的来源解析器，不应复制批注 UI 或存储。
